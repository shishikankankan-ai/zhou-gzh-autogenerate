# 提示词：公众号排版

用途：把定稿正文转成带 HTML 排版的成稿。适用于任何主题。

> 蒸馏自实战里"文章太素"的教训——排版密度不够，内容再好也发灰。

## 复制下面这段到 AI 工具

```
下面是一篇已经定稿的文章：

【粘贴你的定稿正文，包含标题】

请把它转成适合公众号后台的 HTML 排版，要求：

一、技术格式
1. 输出完整的 HTML 片段，可直接粘进公众号编辑器。
2. 样式全部内联（style="..."），不要用 class 和外部样式表（公众号会过滤）。
3. 正文字号 16px，行高 1.75，段间距用 margin 控制。
4. 小标题加粗、字号 18px，和正文有区分。
5. 颜色不超过两种主色。

二、视觉块密度（决定"华丽还是发灰"，必须达标）
6. 引用块（带边框的卡片）：4–6 处，只放金句和关键判断，占比控制在 8%–15%。不要放长段文字和模板代码。
7. 分割线：3–4 条，只放在大节之间。
8. 列表/编号条目：至少 2 组，每组 3–6 条。逐条列举的内容务必用列表，不要挤成一坨。
9. 加粗：只标 3 处最关键的判断句。满屏加粗等于没有重点。
10. 段落：七成以上的段落控制在 60 字以内，超过 80 字的长段全篇不超过 3 处。
11. 每节至少有一句独立成段的短句（4–12 字），用来制造节奏。

三、红线
12. 不改变正文一个字——排版只加结构，不改内容。
13. 不用 emoji，不用装饰性符号堆砌。
14. 只输出 HTML 代码，不要在代码外解释。

排版参数需要调整，参照 prompts/03-layout/style-vars.md。
```

## 填法说明

- 第 6–11 条是重点。实战里反复出现"94 篇华丽、95 篇发灰"，根因就是视觉块密度掉了。**内容一样，密度到位就好看。**
- 引用块只放金句和判断，别塞长段——塞多了会被撑成大花框。
- 公众号会过滤 class 和外部样式，所以必须内联 style。
